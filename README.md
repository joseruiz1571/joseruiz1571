# Jose Ruiz-Vazquez

I build the evidence and assurance layer for AI agent governance: the structured records, attestations, and control mappings that let a system, an auditor, or a buyer verify what an agent did and what it was allowed to do.

Two decades as an information professional taught me how to give unstructured knowledge a shape other people can query; I apply that to policy, risk, and agent behavior in OSCAL, OPA, and signed evidence pipelines mapped to NIST AI RMF, ISO 42001, and the EU AI Act.

The open-source stack is inventory ([mltrack](https://github.com/joseruiz1571/mltrack)) → cards ([governance-card-stack](https://github.com/joseruiz1571/governance-card-stack)) → evidence and custody ([Colophon](https://github.com/joseruiz1571/colophon)) → assurance ([mlassure](https://github.com/joseruiz1571/mlassure)).

## Featured

| Project | What it is |
|---------|------------|
| [**colophon**](https://github.com/joseruiz1571/colophon) | Signed session packet for AI agent tool use that a stranger can verify — custody is provable, judgment is not. |
| [**mlassure**](https://github.com/joseruiz1571/mlassure) | Assesses AI systems against NIST SP 800-53 with a citation invariant: a verdict that cites evidence the run never retrieved fails the run. |
| [**mltrack**](https://github.com/joseruiz1571/mltrack) | AI model inventory mapped to NIST AI RMF, ISO 42001, and SR 11-7, behind a fail-closed CI gate. |
| [**governance-card-stack**](https://github.com/joseruiz1571/governance-card-stack) | Model, System, and Agent Cards on one OSCAL spine, so posture is data a pipeline can gate on. |
| [**grc-pipeline-challenge**](https://github.com/joseruiz1571/grc-pipeline-challenge) | GRC Engineering Club 6-week pipeline challenge on GCP (third place): fail-closed controls and signed evidence an assessor can traverse. [Case study](https://github.com/joseruiz1571/grc-pipeline-challenge/blob/main/PORTFOLIO-CASE-STUDY.md). |
